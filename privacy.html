YOUR DATA AND LIMELIGHT

PRIVACY

Limelight is designed to keep application settings, imported mods, and diagnostic information under the user's control.

Privacy Overview

Limelight is a standalone desktop application. It does not require a Limelight account and does not automatically upload diagnostic reports.

This page also covers the separate Project Encore prototype. Its community leaderboard sends player-linked results to an online service when online access is enabled, as described below.

The Early Access build does not include advertising, behavioural analytics, or hidden usage tracking.

EARLY ACCESS

This page describes Limelight's current Early Access behaviour and Encore's current prototype. It will be reviewed as those features change. Last reviewed: 4 November 2026.

Data Stored Locally

Limelight stores the information needed to preserve your library and application preferences on your Windows account.

  • The connected Dead as Disco directory
  • Imported mod names and local identifiers
  • Mod installation directories
  • Scanned Unreal asset manifests
  • The currently selected mod
  • XLR8 group membership and ordering
  • XLR8 shuffle and input settings
  • Discord Rich Presence preference
  • Optional resource overlay preference
  • Live-session recovery information
  • Local LimelightMP session and diagnostic logs
  • Encore run history, personal bests, pending score submissions, and online configuration
  • Encore's temporary-playthrough recovery journal

Limelight's application data is normally stored beneath:

%LOCALAPPDATA%\Limelight

Imported Mod Files

Imported archives are extracted into Limelight's local mod library. Limelight scans their package information to learn which Dead as Disco assets they replace.

These files remain on the user's computer. Removing a mod through Limelight removes its managed library entry and associated local files.

MOD AUTHOR CONTENT

Imported mod files belong to their respective authors. Limelight does not grant permission to redistribute, reupload, or claim ownership of another creator's work.

Nexus Mods Connection

Nexus Mods account connection, catalogue browsing, and direct downloads are temporarily disabled during Early Access while Limelight's public integration is prepared.

Early Access does not ask ordinary users to provide a personal Nexus Mods API key. Compatible archives downloaded manually through a browser can still be imported into Limelight.

This section will be updated when the approved public authentication flow becomes available.

Discord Rich Presence

Discord Rich Presence is optional. When enabled and the Discord desktop client is open, Limelight can display that the application is being used.

Activity details may include the selected Live Loader mode, game-session state, and the display name of the active mod. Limelight does not request or store the user's Discord password.

Rich Presence can be disabled from Limelight's General settings.

LimelightMP Connections

LimelightMP is an optional experimental feature. When the user chooses Host or Join, it uses the supplied private network address to connect two copies of Dead as Disco and relay the joining player's controls to the host.

The short friend code contains the host address, connection ports, and temporary session authentication information. Limelight does not publish the code or upload it to a Limelight service. Players choose how to share it.

TREAT FRIEND CODES AS PRIVATE SESSION INFORMATION

Send a friend code only to the intended player. Redact the code and Tailscale address from public screenshots, videos, diagnostic excerpts, and bug reports.

Encore Scores and Steam Identity

Encore reads your Steam display name and Steam ID through the Steam API already loaded by Dead as Disco. The Steam ID associates results with the same account. Encore does not ask for your Steam password. If Steam identity is unavailable, results remain local under Local player.

Completed runs are saved locally first. With online access enabled, Encore submits the following information to the community leaderboard hosted on Cloudflare Workers and D1:

  • Your Steam display name and Steam ID
  • Completed rounds, defeated bosses, and combat time
  • The run's finish time and ending reason
  • A unique run ID and the ruleset, game-build, and submission-format identifiers

The service also records when a submission was received. Save files, imported music, mod files, and diagnostic reports are not part of the score submission. The current service address is https://encore-leaderboard.encore-leaderboard.workers.dev.

What other people can read

The public leaderboard returns up to 100 personal-best rows for a ruleset and game build. Each row contains a display name, completed rounds, defeated bosses, combat time, and run ID. Anyone can read or copy these public results, including applications displaying the board in-game or on a website.

Steam IDs, individual finish times, ending reasons, and the full submitted run history are excluded from that public response. The API does not offer public database queries or administrative access. These are independent community scores: the current prototype does not authenticate Steam identity or verify gameplay on the server.

When Steam pictures are enabled on the service, it sends the Steam IDs for leaderboard rows to Steam. It includes the image URL for a public profile when the Steam display name matches the submitted name. The viewer's browser loads the picture from Steam's image service. Players can request removal of their leaderboard data through Support.

Online access and local records

CURRENT PROTOTYPE DEFAULT

Online access is enabled on first launch with the configured service. There is currently no first-use sharing prompt. To disable online fetching and submissions, close the game, set enabled to false in the file below, then restart the game. Keep the other configuration fields unchanged.

%LOCALAPPDATA%\Limelight\Encore\leaderboard-config.json

Disabling online access keeps local scoring available and does not remove previously uploaded results. Run history, personal bests, and pending submissions are stored beneath %LOCALAPPDATA%\Limelight\Encore. Pending submissions may be sent if online access is enabled again.

Retention and removal

The service currently retains accepted runs and run IDs without an automatic expiry. Retained run IDs prevent the same submission being inserted again after a retry. It keeps one personal best per Steam account, ruleset, and game build.

There is currently no in-game deletion control or public deletion API. Use Support to request removal of uploaded Encore data. Removal needs manual action by the service operator and verification of account ownership. Deleting local files alone does not remove server records.

Encore Temporary Saves

Encore uses a temporary playthrough for a run and records the original save selection in %LOCALAPPDATA%\Limelight\Encore\save-journal.json. On cleanup it restores that selection and removes the temporary playthrough. If recovery fails, the journal is kept for a later retry. Shared game settings, music, and GlobalProgress remain shared with the base game.

The journal stays on your computer and is not submitted to the leaderboard. Keep it until any pending restoration has completed; removing it can remove information needed to restore the original save selection.

Diagnostic Reports

Diagnostic reports are created only when the user selects Export Diagnostic Report. Limelight does not automatically upload the resulting file.

A report may contain:

  • Limelight, Windows, and .NET version information
  • Game connection and process status
  • Installed mod count and active mod name
  • Managed loader installation status
  • Live-session status and recent errors
  • Mounted container names, sizes, and switch results
  • Recent relevant UE4SS diagnostic events
THE USER CHOOSES WHETHER TO SHARE

Review the report before sending it. Limelight keeps the exported file on the user's computer until the user chooses to share or delete it.

Resource Overlay

The optional resource overlay reads Limelight's current process resource usage, such as memory consumption. This information is displayed locally and is not transmitted by the overlay.

The resource overlay is disabled by default and can be enabled from General settings.

Third-Party Services

Some Limelight and Encore features communicate with external services. Encore's current online default is explained in the Encore scores section:

  • Steam for launching and validating Dead as Disco, and reading Encore's player identity
  • Cloudflare Workers and D1 for Encore's community leaderboard
  • Tailscale for the optional private LimelightMP route
  • Nexus Mods for catalogue and download functionality
  • Discord for optional Rich Presence
  • GitHub for Limelight source, releases, and documentation

Each external service operates under its own account, privacy, and acceptable-use policies.

The Encore service uses the connecting IP address for request rate limiting through Cloudflare. That address is not stored as a field in the Encore score tables.

Removing Local Data

Individual mods can be removed through My Mods. The Nexus connection can be removed through Settings.

Before removing Encore's local data, allow any pending save restoration to finish. If recovery is unresolved, preserve save-journal.json and use Support before deleting the folder.

Once recovery is complete, close Dead as Disco and Limelight. To remove all Limelight application data, remove the application data folder:

%LOCALAPPDATA%\Limelight

Removing this folder clears saved settings, imported mod metadata, cached catalogue information, and recovery state. It also clears Encore's local score history and pending submissions. It does not remove already uploaded scores. Limelight will behave like a fresh installation the next time it starts.

Encore's online configuration is also removed. With the current prototype, launching Encore again recreates it with online access enabled by default.

Questions or Concerns

Privacy concerns discovered during testing should include the Limelight version, the affected feature, and a clear description of the unexpected behaviour. Never include a Nexus API key in the report.
